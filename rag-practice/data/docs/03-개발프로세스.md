# 누리테크 개발 프로세스

## 브랜치 전략

기본 브랜치는 `main`이며 직접 푸시는 금지되어 있습니다.
모든 작업은 `feature/`, `fix/`, `chore/` 접두사를 붙인 브랜치에서 진행하고
Pull Request를 통해 병합합니다. 브랜치 이름에는 이슈 번호를 포함합니다.
예: `feature/1234-검색-랭킹-개선`

## 코드 리뷰

PR은 최소 1명의 승인이 있어야 병합할 수 있습니다.
결제, 인증, 개인정보를 다루는 코드는 2명 이상의 승인이 필요합니다.
리뷰어는 영업일 기준 1일 이내에 첫 응답을 남기는 것을 원칙으로 합니다.
PR 크기는 변경 400줄 이내를 권장하며, 그보다 커지면 분할을 요청할 수 있습니다.

## 테스트

모든 PR은 CI를 통과해야 합니다. CI는 린트, 유닛 테스트, 타입 체크를 실행합니다.
신규 기능은 유닛 테스트를 함께 작성해야 하며, 전체 커버리지 70% 미만으로
떨어지는 PR은 CI에서 자동으로 차단됩니다.

## 배포

배포는 화요일과 목요일 오후 2시에 진행합니다.
금요일과 공휴일 전날에는 배포하지 않습니다. 단, 심각도 1등급 장애 대응은 예외입니다.
배포는 스테이징 환경에서 최소 24시간 검증을 거친 뒤 프로덕션에 반영합니다.
롤백은 배포 담당자가 단독으로 결정할 수 있으며, 사후에 인시던트 채널에 공유합니다.

## 장애 대응

심각도는 1~4등급으로 분류합니다. 1등급은 전체 서비스 중단, 2등급은 핵심 기능 장애,
3등급은 일부 기능 저하, 4등급은 경미한 버그입니다.
1~2등급 장애는 온콜 담당자가 15분 이내에 인지하고 대응을 시작해야 하며,
장애 종료 후 5영업일 이내에 포스트모템 문서를 작성합니다.
